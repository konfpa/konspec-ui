approvals/views.py @require_POST def approve(request, pk): doc = get_object_or_404(Document.awaiting(request.user), pk=pk) try: doc.approve(by=request.user, on_behalf_of=request.delegation) except AlreadyDecided as e: said = f"{doc.number} was approved by {e.by} at {e.at:%H:%M}, before " said += "your approval reached the server. Nothing was written by you." except Stale: said = f"{doc.number} changed while it was on screen. Nothing was written." else: said = f"{doc.number} approved." queue = list(Document.awaiting(request.user)) said += f" {len(queue)} left in your inbox." response = render(request, "approvals/_inbox.html", inbox_context(request, queue)) response["HX-Trigger"] = json.dumps({"decided": said}) return response Document.awaiting(user) is the whole routing rule in one place — the user's own queue plus anything they hold a live delegation for — and it is re-run on every response, so the queue and the record can never disagree about what is left. It is also what the POST re-checks: a document that has left the queue between the render and the click is not in the queryset, so the 404 is the concurrency guard rather than something bolted on beside it. within_limit and next_approver come off the model against the authority in force, which is the delegation limit when one is being used and the user's own otherwise. The template never compares two figures itself — a limit worked out in a template is a limit that will be worked out differently in the next template. status_dot_class is one of the five locked values — bg-zinc-500, bg-amber-500, bg-red-600, bg-emerald-600, bg-zinc-400 — so the pill shape is written once here and only the dot changes. {% endcomment %}
